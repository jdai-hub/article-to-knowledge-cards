# Make Knowledge Cards

把一个 Agent Skill 装进你的助手：把粘贴的文章或本地 Markdown/TXT 文件，提炼成 **5～8 张知识卡片**，并在项目根目录下按核心关键词建立目录，把每张卡片导出为独立的 PNG 图片。

macOS 用户也可以直接双击 `文章转卡片.app`，粘贴文章后点一个按钮完成转换，不需要命令行。

每张卡片包含：

- **标题**
- **核心知识**（一句话说清一个知识点）
- **简明解释**（2～4 句）
- **例子或自测问题**（二选一）

## 设计原则

- 只提取真正重要的知识，不做全文复述
- 一张卡片只讲一个知识点
- 合并重复和高度重叠的内容
- 不编造原文没有的人名、数字、因果或结论
- 原文信息不足时，如实减少卡片数量，不强行凑数
- 卡片语言默认与原文一致
- 每次生成卡片时，自动按关键词建立目录并导出 PNG

## 目录结构

```text
skills/make-knowledge-cards/
├── SKILL.md
├── agents/openai.yaml
└── scripts/
    ├── render_cards.py
    └── requirements.txt

app/                       # macOS 图形界面
├── card_app.py
├── icon.py
└── build_app.sh

dist/文章转卡片.app         # 构建产物，不提交
```

Skill 本身只包含一个用于渲染 PNG 的脚本。`app/` 是独立的图形界面包装，调用同一个 Skill，不参与 Skill 的文本流程。

## 安装

需要 Python 3.9+ 和 Pillow：

```bash
python3 -m pip install -r skills/make-knowledge-cards/scripts/requirements.txt
```

也可以不全局安装，直接用 `uv` 运行渲染脚本：

```bash
uv run --with pillow python skills/make-knowledge-cards/scripts/render_cards.py ...
```

渲染需要支持卡片语言的字体。macOS 会自动使用 Hiragino Sans GB，Windows 会查找微软雅黑；Linux 如果没有中文字体，可安装 Noto Sans CJK，例如：

```bash
sudo apt install fonts-noto-cjk
```

把 `skills/make-knowledge-cards` 放到所用 Agent 的 Skills 目录，例如：

- Codex：`~/.agents/skills/` 或项目内 `.agents/skills/`
- Claude Code：`~/.claude/skills/` 或项目内 `.claude/skills/`

重新加载会话后即可使用。

## 图形界面（macOS）

不想用命令行时，可以构建一个可双击的应用：

```bash
./app/build_app.sh
```

生成 `dist/文章转卡片.app`，双击打开后：

1. 把文章粘贴到文本框（⌘V），或点「粘贴」
2. 点「一键生成卡片」
3. 完成后点「在 Finder 中打开」

转换由本机 `opencode` CLI 调用模型完成，通常需要 30～120 秒，窗口会显示进度，不会卡死。首次使用前需要：

- 已安装并登录 `opencode`（`opencode auth login`）
- 已安装 `uv`（用于自动选择带 Tk 9 的 Python，并渲染 PNG）

界面上的「更改」可以切换项目目录；应用会把选择保存在
`~/Library/Application Support/Make Knowledge Cards/config.json`。

应用图标和 `.app` 都是构建产物，不提交到仓库。

## 使用

直接粘贴文章：

```text
把下面这篇文章整理成知识卡片：

<粘贴文章正文>
```

或指定本地文件：

```text
用 $make-knowledge-cards 读取 ./article.md，生成知识卡片
```

也可以直接说「把这篇文章拆成知识卡片」「生成学习卡片」等，Skill 会根据描述自动触发。

## 输出文件

每次生成卡片时，会在项目根目录下创建一个以核心关键词命名的目录：

```text
<项目根目录>/
└── <关键词>/
    ├── card-01.png
    ├── card-02.png
    └── ...
```

- 关键词从卡片内容中提取，优先选择贯穿多张卡片的核心术语，而不是「方法」「总结」这类通用词。
- 目录名中的空格和路径非法字符会替换为 `-`。
- 每张 PNG 对应一张卡片，宽度默认 1200px，高度随内容自动调整。
- 如果同名目录已存在，会自动追加 `-2`、`-3`，不会覆盖旧文件。
- PNG 目录中只放图片；临时 Markdown 文件会在渲染后删除。

## 输入输出示例

**输入**（`olive-oil.txt`）：

```text
- 特级初榨橄榄油是冷榨得到的，酸度较低，适合凉拌或低温烹饪。
- 橄榄油的主要成分是单不饱和脂肪酸，其中油酸含量较高。
- 买橄榄油时看采摘日期比看保质期更有意义，因为风味会随时间下降。
```

**输出**：

> 原文信息有限，共提炼出 3 张卡片。

### 卡片 1：特级初榨橄榄油适合凉拌或低温烹饪

- **核心知识**：特级初榨橄榄油是冷榨得到的，酸度较低，适合凉拌或低温烹饪。
- **简明解释**：冷榨和低酸度是它的特点，原文据此推荐凉拌或低温烹饪。
- **例子或自测**：特级初榨橄榄油更适合高温煎炸还是凉拌？原文说适合凉拌或低温烹饪。

### 卡片 2：橄榄油的主要成分是单不饱和脂肪酸

- **核心知识**：橄榄油的主要成分是单不饱和脂肪酸，其中油酸含量较高。
- **简明解释**：单不饱和脂肪酸是橄榄油的主要脂肪类型，油酸是其中含量较高的具体成分。
- **例子或自测**：橄榄油中含量较高的单不饱和脂肪酸是什么？油酸。

### 卡片 3：买橄榄油应优先看采摘日期

- **核心知识**：买橄榄油时看采摘日期比看保质期更有意义，因为风味会随时间下降。
- **简明解释**：保质期不能反映风味的新鲜程度，采摘日期更能说明油的风味状态。
- **例子或自测**：为什么买橄榄油要看采摘日期？因为风味会随时间下降。

> 示例原文只有 3 个有效知识点，因此输出 3 张而不是凑到 5 张。信息量正常的文章通常会输出 5～8 张。

生成的文件：

```text
橄榄油/
├── card-01.png
├── card-02.png
└── card-03.png
```

## 支持范围

**支持**

- 粘贴的文章正文
- 本地 `.md` / `.txt` 文件
- 每张卡片导出为独立 PNG
- macOS 图形界面（双击 `.app`，粘贴后一键生成）

**暂不支持**

- 网页抓取
- PDF
- Anki 导出

## 测试情况

已使用科普说明文、操作指南、英文议论文、信息稀少短文和重复内容较多的文章进行测试，覆盖了卡片数量控制、去重、单卡单知识点、语言跟随原文和不编造信息等要求。

PNG 渲染也已验证：中文 8 张卡片、英文 2 张卡片、关键词目录命名、同名目录自动追加后缀，以及不同内容长度下的自适应高度。

图形界面已做端到端测试：粘贴短文 → 调用 `opencode` → 生成 3 张卡片 → 输出到关键词目录，全程约 27 秒；`.app` 可正常启动，图标、Info.plist 和 ad-hoc 签名均校验通过。
